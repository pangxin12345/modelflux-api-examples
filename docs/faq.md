# 常见问题

## API 的 Base URL 和请求路径是什么？

默认 Base URL 是 `https://modelflux.cn/v1`。客户端向它发送 `POST /chat/completions`，完整默认端点为 `https://modelflux.cn/v1/chat/completions`。在客户端配置时要确认它要求的是基础地址还是完整端点，避免重复拼接路径。

## 如何设置 API Key？

通过 `MODELFLUX_API_KEY` 环境变量传入。`.env.example` 只是模板，示例脚本不会自动加载 `.env`。可参见[快速开始](quickstart.md)中的 macOS/Linux 和 PowerShell 示例。不要把密钥提交到仓库、贴到公开问题或截图。

## 需要什么权限？

使用自己的 ModelFlux 账户密钥，并确认账户状态及该密钥对所选模型有访问权限。实际可用模型、权限和账户条件以平台账户显示的信息为准。遇到 `401` 或 `403` 时结合响应正文检查认证和访问权限；不要在公开反馈中粘贴密钥。

## 调用免费吗？

不能假设免费。API 调用可能收费，价格和计量规则可能变化；请在运行前查看[价格页面](https://modelflux.cn/pricing)并在账户中核对用量。模型名中出现 `-free` 也不保证请求免费。

## 为什么请求模型名和响应中的 model 不一样？

本次记录使用的请求模型标识是 `deepseek-flash`，服务响应字段是 `deepseek-v4.1-flash`。请以[验证记录](validation.md)中的实际观察为准。响应名称只是接口返回的字符串，不能单独证明底层模型身份或渠道来源；其他请求和时间可能返回不同值。

## 流式、工具调用或多模态可以用吗？

本仓库的三个示例只覆盖非流式文本对话。流式响应、工具调用、多模态输入输出、容灾能力和长期稳定性均未验证。兼容接口的请求形式不代表所有功能都一致，参见[兼容范围](compatibility.md)。

## 报错后怎么排查？

结合 HTTP 状态码与响应正文中的 `error` 内容判断，状态码本身只是线索。检查 Base URL、模型标识、密钥、账户权限和用量；参见[故障排查](troubleshooting.md)。示例没有自动重试，尤其不要对 5xx 或超时做无限重试，因为服务端可能已经处理请求，重复调用也可能产生费用。不要为了排错公开授权头或未脱敏的响应内容。

## 运行示例会自动读取 `.env` 吗？

不会。请手动将环境变量导入当前 shell，或在 PowerShell 中设置变量，再从仓库根目录运行脚本。只加载自己编辑并检查过的 `.env` 文件。

## 仓库许可证涵盖什么？

本仓库的文档与示例代码按 MIT 许可证提供。ModelFlux 在线服务按其平台规则另行计费；模型权重不在仓库中，也不属于本仓库许可证范围。项目不声称与模型厂商官方关联。

## 如何反馈安全问题？

请不要在公开 Issue、讨论、截图或日志中贴出密钥或可利用的细节。若密钥已泄漏，请立即在账户中撤销并轮换。请通过官网账户内现有的私有客服渠道报告；如果托管仓库页面明确启用了私密安全报告功能，也可使用该功能。详情见 [SECURITY.md](../SECURITY.md)。
