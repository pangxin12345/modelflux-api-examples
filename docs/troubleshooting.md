# 故障排查

先确认运行命令是在仓库根目录执行，并检查 `MODELFLUX_API_KEY` 已设置、没有保留占位符，且 `MODELFLUX_BASE_URL` 与 `MODELFLUX_MODEL` 拼写正确。脚本不会自动读取 `.env`。

发生 HTTP 错误时，应结合状态码和响应正文中的 `error` 内容判断原因。状态码只能作为线索，不能单独确定账户、模型或请求的具体问题。

cURL 使用 `--fail-with-body`，非成功 HTTP 响应会返回非零退出码并保留错误正文。Python 和 Node 示例只输出状态码或概括错误，详细信息请在私有控制台日志中查看；不要为排错把完整授权头打印出来。Python 的超时是网络操作超时，cURL/Node 的示例设置了约 90 秒请求时限。

| 状态码/现象 | 建议检查 |
|---|---|
| `400` | 查看错误正文，检查 JSON 请求参数、模型名及服务端支持情况。 |
| `401` 或 `403` | 检查密钥是否存在、复制完整、有效，以及账户是否有访问权限。不要把密钥贴到反馈中。 |
| `404` | 核对 Base URL 和 `/chat/completions` 路径，以及模型是否可用。 |
| `429` | 查看错误正文和账户用量/限流信息；不要通过紧密循环重复请求。 |
| `5xx` | 查看错误正文并稍后人工判断是否再试。示例没有自动重试；不要无限重试，避免加重故障或产生额外请求与费用。 |
| 网络或超时错误 | 检查网络连通性、代理和服务可用状态；确认是否收到服务端响应，再决定是否重试。 |
